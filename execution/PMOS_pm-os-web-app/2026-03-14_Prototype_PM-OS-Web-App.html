Research Sources

This synthesis draws from:

  • PM OS CLAUDE.md — Phase 8 goals, current architecture, user personas
  • pm-os-reference/identity/STRATEGY.md — Vision, mission, North Star metrics
  • identity/STANDARDS.md — Engineering standards, platform profiles
  • Session context — Direct PM input on problem space and target users
  • PM OS architecture observation — Derived from actual system design
This is a first-party product discovery. No external customer interviews exist yet. Opportunities marked [ASSUMPTION — validate] require validation with 2+ additional non-power-user PMs before committing to feature set.

Insights Summary

Theme 1: CLI Gatekeeping Blocks Team Adoption

  • Frequency: 3/5 sources · Severity: High
  • Evidence: "PM OS Phase 8 goal: 5+ PMs using concurrently, onboarding < 2 hours" — CLAUDE.md
  • Evidence: "Current users: primarily 1 PM (power user, Claude Code native)" — direct PM context
  • Implication: The gap from 1 → 5+ users is a UX problem, not a capability problem. PM OS already does everything needed; it's inaccessible without CLI fluency.

Theme 2: Artifacts Are Invisible Without Repo Access

  • Frequency: 3/5 sources · Severity: High
  • Evidence: "PM OS artifacts live in execution/ folders" — direct PM context
  • Evidence: Confluence auto-publish covers only 6 skills, requires manual trigger
  • Implication: PM OS produces high-quality artifacts that few people can consume. A web browse layer eliminates this distribution bottleneck.

Theme 3: Onboarding Is Unguided and PM-Dependent

  • Frequency: 2/5 sources · Severity: High
  • Evidence: "Onboarding < 2 hours" Phase 8 target implies current state is worse
  • Implication [ASSUMPTION — validate]: Each new PM relies on the power user to onboard them. This doesn't scale to 5+ users.

Prioritized Opportunities

  • 🥇 Enable non-CLI PMs to access and use PM OS (score: 9)
  • 🥇 Make artifacts browsable + shareable without repo access (score: 9)
  • 🥈 Guided onboarding that doesn't require PM hand-holding (score: 7)
  • 🥉 Role-aware views for engineers, designers, execs (score: 5)
