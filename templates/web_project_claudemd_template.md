## Component Library

- **Install**: `pnpm dlx shadcn@latest add [component]` — never copy from docs
- **`components/ui/`**: auto-generated by shadcn CLI — DO NOT modify directly
- **Custom components**: create wrappers in `components/[feature]/` that compose ui/ primitives
- **Shared compositions**: `components/shared/` for cross-feature reusables
- **Theme**: CSS variables in `globals.css` using `oklch()` — never hardcoded hex/rgb
- **Dark mode**: `class` strategy

Quick reference:
| Need | Component |
|------|-----------|
| Modal with form | Dialog |
| Side panel / filters | Sheet |
| Mobile bottom actions | Drawer (Vaul) |
| Confirmations | AlertDialog |
| Menu actions | DropdownMenu |
| Form field selection | Select / Combobox |
| Notifications | Sonner |
| Data display | Table + DataTable |

### Plugin Workflow Sequence

Use plugins in this order during feature development:

1. **`/feature-dev`** — structured 7-phase build from PM OS spec
2. **`/security-guidance`** — activate at session start for auth/API/AI work
3. **`/typescript-lsp`** — type check after each file (passive, always available)
4. **`/frontend-design`** — production-grade UI from prototype
5. **`/code-review`** — after feature complete, before commit
6. **`/commit-commands`** — commit + push
7. **`/pr-review-toolkit`** — before marking PR ready for review

### Feature Development

1. Read PM OS spec from `execution/[slug]/`
2. Create branch: `feature/[JIRA-KEY]-[description]`
3. Use `/feature-dev` plugin for structured 7-phase implementation
4. TDD cycle: Zod validators → Server Actions → Components → E2E
5. Commit: `feat(scope): description (JIRA-KEY)`
6. Push → CI runs → Vercel preview deploy
7. PR review with `/code-review` and `/pr-review-toolkit`
8. Merge → Vercel production deploy

## Quality Gates

### Before Merge

- [ ] `pnpm tsc --noEmit` — no type errors
- [ ] `pnpm biome check .` — lint + format clean
- [ ] `pnpm test` — unit + component tests pass
- [ ] `pnpm test:e2e` — Playwright E2E tests pass (affected flows)
- [ ] No new `any` types without justification
- [ ] Zod validators for all external inputs
- [ ] Interactive elements keyboard-navigable (WCAG AA)
- [ ] shadcn/ui primitives used (not raw HTML for complex UI)

### CI Pipeline (GitHub Actions)

Runs on every push to `main` and every PR:
1. Type check: `tsc --noEmit`
2. Lint + format: `biome check .`
3. Unit + component tests: `vitest --coverage`
4. Security audit: `pnpm audit`
5. E2E tests: `playwright test` (when enabled)

## Security

- No hardcoded secrets — all credentials in `.env` (gitignored)
- Zod validation at all system boundaries (Server Actions, API routes)
- Drizzle ORM parameterized queries only (no raw SQL concatenation)
- No `dangerouslySetInnerHTML` without DOMPurify sanitization
- Server Actions use Next.js built-in CSRF protection
- IDOR prevention: every query includes `WHERE userId = session.user.id`
- Security headers configured in `next.config.ts` (CSP, X-Frame-Options, etc.)
- `pnpm audit` in CI — no critical vulnerabilities
